什么是 AI Agent
核心定义
Google 官方定义(2024 白皮书)
:生成式 AI Agent 是一个
应用程序
,通过观察周围世界并使用可用的工具来实现其目标。Agent 具有自主能力(autonomous),只要提供了合适的目标,它们就能独立行动,无需人类干预;即使是模糊的人类指令,Agent 也可以推理出下一步行动并最终实现目标
[1]
。
Anthropic 定义
:LLM 动态指导自身流程和工具使用,保持对完成任务方式的控制。相比之下,通过预定义代码路径协调工具的系统应称之为
Workflows
,两者统称"Agentic System"
[2]
。
学术定义(复旦大学综述)
:自主智能体通过
感知环境、规划解决方案和执行动作
来完成设定的目标任务,是实现通用人工智能(AGI)的有前景的技术途径
[3]
。

02
核心架构组件
业界存在三套主流架构视图,互为补充,分别从不同角度描述了 Agent 的内部结构。
Google 三组件架构
Google 2024 白皮书提出 Agent 由三个核心组件构成,形成
认知架构 (cognitive architecture)
[1]
:
模型 (Model)
作为核心决策的语言模型,能遵循 ReAct、Chain-of-Thought、Tree-of-Thoughts 等推理框架。可以是通用、多模态或微调模型。
工具 (Tool)
解决基础模型无法与外部世界联动的瓶颈。常见形式包括 Web API、Extensions、Functions、Data Stores 等。
编排层 (Orchestration)
一个循环过程:接收信息 → 内部推理 → 使用推理结果指导下一步行动。核心是维护记忆、状态、推理和规划。
复旦大学三模块架构
复旦 NLP 实验室在《The Rise and Potential of Large Language Model Based Agents》中提出
[4]
:
大脑 (Brain)
:作为控制器,承担记忆、思考和决策
感知 (Perception)
:感知并处理来自外部环境的多模态信息
动作 (Action)
:使用工具执行并影响周围环境
Lilian Weng 四要素模型
OpenAI 前研究员 Lilian Weng 提出被广泛引用的框架
[2]
:
LLM Powered Autonomous Agent = 规划 + 记忆 + 工具使用 + 行动

MCP:Agent 生态的"USB 接口"
MCP (Model Context Protocol)
由 Anthropic 于 2024.11 发布,2025.12 捐赠给 AAIF 基金会。它解决了"N 个模型 × M 个工具"的集成困境,提供标准化的"USB-C 接口"
[17b]
。
架构:
LLM Agent → MCP Client → MCP Server → 实际工具 (API/DB/脚本)
[16b]
MCP 核心优势
:模型无关(支持 GPT、Claude、开源模型等)、工具可热插拔、版本管理、运行时动态注册/卸载、支持上下文感知(根据用户身份动态暴露工具)、无厂商锁定
[16b]
[17b]
。
截至 2026 年 3 月,MCP SDK 月下载量达 9700 万,GitHub 81000+ Stars,Anthropic、OpenAI、Google、Microsoft、Hugging Face、LangChain 已全面支持

规划算法深度解析
规划是 Agent 将模糊的用户目标转化为可执行步骤序列的核心能力。不同规划算法在
灵活度
、
可控性
和
计算成本
之间做出不同权衡。2025 年以来,规划算法已从单一线性分解发展为包含
树搜索
、
图结构
、
动态重规划
在内的完整技术族系。
任务分解 (Task Decomposition)
Plan-and-Solve Prompting
Wang 等人于 2023 年提出,是 ReAct 的进阶版本
[29]
。核心思想:先生成整体计划(Plan),再逐步执行(Solve),通过分离规划与执行来减少推理中的认知负荷。实践中通常维护
Plan-and-Execute 状态机
,跟踪
task → goal → plan → executed_tasks → results → current_phase
的完整生命周期
[29]
。
HuggingGPT
Microsoft 于 2023 年提出,LLM 作为中央控制器,将用户任务分解为子任务,并为每个子任务选择合适的专家模型
[30]
。四步流程:
任务规划 → 模型选择 → 任务执行 → 响应生成
。通过 HuggingFace 模型库动态调度数百个专用模型,LLM 不直接执行所有任务,而是通过接口调用外部模型,形成"LLM 即指挥家"的范式。其关键贡献在于证明了 LLM 可以作为
异构 AI 模型的协调中枢
,为后续的多模型编排系统奠定了基础。
Least-to-Most Prompting
Google 研究者提出,将复杂问题分解为由易到难的子问题序列,先解决简单子问题,再将其答案作为上下文解决更难的子问题
[31]
。与 Plan-and-Solve 不同,Least-to-Most 强调
子问题之间的依赖关系
,后一步的解决依赖前一步的结果,形成递进式推理链。在多跳问答(Multi-hop QA)和数学推理任务上表现优异。
DEPS (Decompose-Predict-Select)
DEPS 框架在机器人控制领域提出,将任务分解为三个阶段:
分解(Decompose)→ 预测(Predict)→ 选择(Select)
。Agent 先将任务分解为子目标,预测每个子目标的可行执行方案,再从多个候选方案中选择最优路径。该框架特别适合
具身智能(E Embodied AI)
场景,因为物理环境中动作的可行性与环境状态紧密耦合。
树与图搜索规划
LATS (Language Agent Tree Search)
Zhou 等人将蒙特卡洛树搜索(MCTS)引入 LLM Agent 规划
[32]
。LATS 将 Agent 的决策过程建模为树搜索,每个节点代表一个状态,通过
价值函数评估
、
UCT 选择
和
回溯更新
来探索最优行动路径。与贪心式的 ReAct 相比,LATS 能在
探索-利用之间取得平衡
,在 WebArena 和 HotPotQA 上刷新了 SOTA。其代价是
Token 消耗显著增加
(通常 5-10 倍),适合对正确率要求极高的场景。
Graph of Thoughts (GoT)
Besta 等人将思维链从线性结构推广为图结构
[33]
。在 GoT 中,推理步骤可以
分支
(一个节点产生多个后续)、
合并
(多个节点汇聚为一个)和
循环
(回溯到之前的节点)。这使得 Agent 能够:
并行探索多条推理路径 → 交叉验证 → 合并最优结论
。在排序、关键词计数等需要全局视角的任务上,GoT 显著优于线性的 CoT。
Tree of Thoughts (ToT)
Yao 等人提出的 ToT 是 GoT 的前身,将推理组织为树形结构,在每个节点进行
状态评估
和
剪枝
[34]
。ToT 的核心贡献是引入了"自我评估"机制:Agent 在搜索过程中可以评估当前路径的前景,决定是继续深入还是回溯。在 24 点游戏中,ToT 的成功率从 CoT 的 4% 提升到 74%。
动态重规划与反思
Reflexion 中的重规划
Reflexion 框架中,Agent 在执行失败后会生成
语言化的反思(verbal reflection)
,将失败原因编码为文本反馈,注入下一轮的提示中
[11]
。这种基于自然语言的"强化学习"不需要更新模型参数,仅通过
episodic memory
的文本积累就能持续改进策略。在 HumanEval 编程任务上,Reflexion 将 GPT-4 的 pass@1 从 80% 提升到 91%。
SelF-Discover 与自适应规划
SelF-Discover 让 Agent
自行发现
推理结构:先从任务描述中提取关键约束,再构建针对该任务的推理蓝图,最后按蓝图执行
[35]
。这种"元规划"能力使 Agent 不再依赖固定的推理模板,而是
为每个新任务定制规划策略
。在 BIG-Bench-Hard 上,SelF-Discover 在 21/23 个任务上超越 CoT。

Agentic RAG:检索增强的智能体化演进
传统 RAG(Retrieval-Augmented Generation)是"检索-读取"的单次管道,而
Agentic RAG
将 Agent 的自主决策能力引入检索过程,使检索变为
多轮、自适应、可纠错的智能行为
[36]
。
传统 RAG 的局限
标准 RAG 管道存在三大瓶颈:
检索质量瓶颈
单次向量检索难以处理多跳问题,低质量检索结果直接污染生成。
缺乏自我纠错
如果首次检索未命中,系统无法自主重试或改写查询。
无工具选择能力
所有查询走同一管道,无法根据问题类型选择不同检索策略。
CRAG:Corrective RAG
Yan 等人提出的 CRAG 在检索后增加了一个
检索评估器(Retrieval Evaluator)
,对检索到的文档质量进行打分
[37]
。根据评估结果,系统选择三种策略之一:
Correct
:检索质量高 → 对文档进行精炼(去噪)后使用
Incorrect
:检索质量低 → 触发 Web 搜索补充信息
Ambiguous
:质量不确定 → 同时使用检索结果和 Web 搜索
CRAG 的关键贡献是将
置信度评估
引入 RAG 管道,使系统具备初步的自我纠错能力。在多个 QA 数据集上,CRAG 比标准 RAG 提升 10-30%。
Self-RAG:自反思 RAG
Asai 等人训练了一个能够
自我反思
的 RAG 模型
[38]
。Self-RAG 通过特殊的反思标记(reflection tokens)来控制四个关键决策:
反思标记
决策内容
作用
[Retrieve]
是否需要检索
避免不必要检索,降低延迟
[IsRel]
检索结果是否相关
过滤噪声文档
[IsSup]
生成是否被支持
检测幻觉
[IsUse]
回答是否有用
质量自评
Self-RAG 通过
强化学习训练
让模型学会这些反思标记的生成,而非依赖外部规则。这使得反思行为内化为模型能力,推理时无需额外提示工程。
Adaptive RAG:自适应检索
Jeong 等人提出根据
查询复杂度
动态选择检索策略
[39]
。系统先对查询进行分类:
简单查询
(如事实查找)→ 单次检索 + 直接生成
复杂查询
(如多跳推理)→ 多轮检索 + 迭代推理
无需检索
(如常识问题)→ 直接生成
查询分类器是一个轻量级分类模型,训练数据来自查询-答案对的复杂度标注。Adaptive RAG 在保持答案质量的同时,平均减少 40% 的检索调用。
Agentic RAG 的完整架构
将上述技术整合,一个完整的 Agentic RAG 系统包含以下层次:
查询分析层
→
策略选择层
→
多源检索层
→
结果评估层
→
反思重检层
→
合成生成层
每一层都由 LLM Agent 驱动决策,而非固定管道。Agent 可以在检索结果不理想时自主改写查询、切换数据源(向量库/Web/知识图谱)、甚至回溯重新规划。

Agent 高级设计模式
Anthropic 在《Building Effective Agents》中系统梳理了 Agent 工程中的设计模式
[2]
。这些模式是
可复用的架构构件
,帮助开发者避免从零设计。2025 年以来,社区在此基础上进一步发展出更丰富的模式库。
核心工作流模式
1. Prompt Chaining(提示链)
将复杂任务分解为
固定顺序的 LLM 调用链
,每一步的输出作为下一步的输入。与 Agent 的自主决策不同,Prompt Chaining 的流程是
预先确定的
,适合步骤明确且不可变的场景。
# 典型 Prompt Chain: 文档翻译
step1 = llm("提取文档中的关键术语表", document)
step2 = llm("使用术语表翻译文档", document, step1.output)
step3 = llm("校对翻译,确保术语一致", step2.output, step1.output)
2. Routing(路由分发)
根据输入特征将请求
分发到不同的处理路径
。路由器可以是一个 LLM 调用(语义路由)或一个分类模型(快速路由)。
语义路由
LLM 理解查询意图后选择路径,灵活但延迟较高。
规则路由
基于关键词/正则匹配,速度快但覆盖面有限。
学习路由
训练轻量分类器自动学习路由策略,平衡速度与灵活性。
3. Parallelization(并行化)
将一个任务拆分为
多个独立子任务并行执行
,再聚合结果。两种常见变体:
Sectioning
:将文档分段,每段独立处理,最后合并
Voting
:对同一问题运行 N 次,通过多数投票决定最终答案(降低单次幻觉)
4. Orchestrator-Workers(编排者-执行者)
一个中央
编排 Agent
将任务分配给多个
执行 Agent
,执行者完成后将结果汇报给编排者。与 Prompt Chaining 的区别:任务分配是
动态的
,编排者根据任务内容决定分几个执行者、分给谁
[2]
。
5. Evaluator-Optimizer(评估-优化)
一个 Agent 负责生成内容,另一个 Agent 负责
评估质量

推理加速技术
KV Cache 优化
LLM 推理中,KV Cache 的命中率直接影响延迟。Agent 场景下,由于多轮对话共享前缀,
前缀缓存(Prefix Caching)
可显著减少重复计算。vLLM 的 PagedAttention 和 SGLang 的 RadixAttention 都针对此场景做了深度优化
[40]
。
推测解码(Speculative Decoding)
使用一个小模型快速生成候选 Token,大模型并行验证。如果小模型的预测正确率高,实际吞吐量可提升 2-3 倍
[41]
。在 Agent 场景中,推测解码特别有效,因为 Agent 的输出通常有固定格式(如 JSON 工具调用),小模型容易学习。
批量推理(Continuous Batching)
将多个请求的 Token 动态打包,在 GPU 上并行计算。vLLM 的 continuous batching 机制可以在不增加单请求延迟的前提下,将吞吐量提升 5-10 倍
[40]
。这对高并发 Agent 服务至关重要。
Token 消耗优化
上下文压缩
长对话中,历史消息会持续增加 Token 消耗。有效的压缩策略:
摘要压缩
:每 N 轮用小模型摘要旧消息,将 1000 Token 压缩到 200
选择保留
:仅保留工具调用和结果,丢弃中间推理步骤
实体提取
:从旧消息提取关键实体和关系,以结构化形式存储
模型路由与级联
不同复杂度的步骤使用不同模型:
# 级联策略
if query_complexity == "simple":
 response = small_model(query) # 快速便宜
 if confidence(response) < 0.8:
 response = large_model(query) # 兜底
elif query_complexity == "complex":
 response = large_model(query) # 直接用大模型

70% 的简单查询可以由小模型处理
,总体成本降低 50-60%。
